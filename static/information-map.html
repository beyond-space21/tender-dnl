How information moves

Seven stages from the public portal to the local catalog. Each stage writes a durable artifact.

01

Closing list

14-day GePNIC list · tender id, title, org, dates, page #

02

Detail page

Critical dates, fee/EMD, docs table, corrigendum list

03

ZIP packet

Captcha-gated download · notice, PDFs, BoQ xls

04

Corrigendum

History popup · revised dates · optional PDF

05

Extract

Page + BoQ parse · Gemini on PDFs · merge

06

Stores

Postgres catalog · Typesense file text · disk

07

Dashboard

Cards, search, export, corrigendum change view

Documents we collect

Two sources: the captcha ZIP (main packet) and the corrigendum history popup (when a corrigendum exists).

From ZIP

Tender notice (NIT)

Official notice from the NIT documents table on the detail page.

  • Tendernotice_1.pdf
  • classified → files.tender_notice

Matched by Document Name from the NIT table.

From ZIP

Tender / work-item PDFs

Technical bid, price bid, conditions, schedules, and other typed work-item documents.

  • TB.pdf · PB.pdf · TenderDocument.pdf
  • TenderCondition.pdf · *schedule*.pdf
  • classified → files.tender_document

Names vary by department; type comes from the Work Item Documents table.

From ZIP

Bill of Quantities

Excel BoQ used for estimated value and work name when the page is thin.

  • BOQ_<id>.xls / .xlsx
  • classified → files.boq

Parsed deterministically (no LLM) for item count and totals.

Corrigendum path

Corrigendum PDF + history

Pulled from “View Corrigendum History”, not from the ZIP.

  • corrigendum.pdf (when Document Name is set)
  • history.html · history.json
  • metadata.json · pdf_sha256

Fee-type corrigenda often have no PDF (pdf_missing); history dates are still kept.

Structured fields — by source

Final details.fields merges sources with precedence: page/BoQ beat Gemini; a later corrigendum overlays only what it changes.

Field Sources Notes
tender_id, title, organisation listpage List row first; detail page refreshes title/org chain
published_at, closing_at, opening_at listpagecorr Critical dates; corrigendum history can revise closing/opening
Pre-bid meeting date / place page From detail Critical Dates / place fields
tender_fee_inr, emd_inr pagellmcorr Page preferred; Gemini fills gaps; corr may override
work_value_inr pageboqllm Tender value → BoQ estimated total → Gemini estimate
eligibility, eligibility_percent llmpage Mostly PDF-only; page tenderer class as fallback
scope_of_work / work description llmpage Gemini summary from notice PDFs when page is thin
Location, pincode, category, contract type, covers page Deterministic detail-page captions
Period of work, bid validity, inviting authority pageboq Authority name also from BoQ header when present
has_corrigendum + change list corr History diffs + optional Gemini on corrigendum PDF

On-disk packet layout

One folder per tender under TENDERS/<id>/. The ZIP is extracted flat; corrigenda live in a subfolder. 

TENDERS/2026_ORG_123456_1/
├── Tendernotice_1.pdf          # NIT
├── TB.pdf · PB.pdf             # work-item docs
├── BOQ_850490.xls             # bill of quantities
├── corrigenda.json            # list snapshot
├── details.json               # merged fields + files map
└── corrigendum/
    └── 1_Date_Extension/
        ├── corrigendum.pdf
        ├── history.html
        ├── history.json
        └── metadata.json         # sha256, dates

Also stored outside the folder

  1. PostgreSQL tenders — catalog row, status, details JSONB, corrigenda, timings, left_list_at
  2. Typesense tender_files — extracted text from packet files for search
  3. temp/ — working ZIP/captcha images during download

Jobs that fill the map

Each dashboard job writes a different slice of the information above.

List pages

Walk the closing list (incremental early-stop). Upserts seen tenders.

→ list fields · list_page · list_sweep

Download new

Open detail, ZIP via captcha session, corrigenda, extract fields.

→ packet files · details · timings

Refresh corrigenda

Re-check open downloads; SHA-256 compare PDFs; detect new releases.

→ corrigendum/* · field overlays

Extract fields

Rebuild details from disk (optional live page parse if missing).

→ details.fields · status

Index files

Push packet text into Typesense for full-text file search.

→ tender_files collection

Export

Spreadsheet of merged fields + corrigendum flags for operators.

→ xlsx / csv
